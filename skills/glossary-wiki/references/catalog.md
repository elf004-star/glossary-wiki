# 父级与全局汇总

## 总目录

`CATALOG_ROOT`（默认 `~/.glossary-wiki/catalog/`，可用环境变量 `GLOSSARY_WIKI_CATALOG` 覆盖，解析顺序见 SKILL.md）中 `index.md` 是总入口，`GLOSSARY.md` 是总术语入口；首次 ingest 时创建。catalog 属于用户数据，不在技能安装目录内，技能升级或重装不得触碰。

`registry.json` 保存 wiki_id、project_id、title、当前 root、parent_wiki_id、status、ftag 标签、上次核实时间与输出摘要。`config.json` 保存 `catalog_root`、search_roots 与分类阈值；其中 `catalog_root` 只是**自述记录**，用于 lint 核对 catalog 是否被移动过，不能作为发现机制——它在 catalog 内部，读它之前必须已经知道 catalog 在哪，位置始终由 SKILL.md 的解析顺序决定。初始 search_roots 使用实际项目所在父目录；需要更大搜索范围时按用户给出的目录扩充。

总 index 只引用各处的 index，不复制知识页。总术语表收录全部权威条目的投影，按 `(project_id, concept_id)` 去重；保留相关 wiki 列表。同名不同概念必须展示“术语 — 项目 — 定义”，绝不能仅按名字合并。若原项目失联，投影保留但标为不可验证，不能作为当前可靠证据。

## 自底向上

1. 从本次更新 wiki 到所有登记的祖先（包含物理上层尚未登记但存在 wiki 的目录）逐层同步。祖先没有 wiki 时无需为了传播自动创建。
2. 汇总父级自有术语与所有子级术语，按概念 ID 去重、按项目校验名称唯一性；定义和来源来自权威条目，覆盖“所有后代”而非仅本批变化。
3. 更新父 index 的子索引链接、覆盖摘要和输出摘要；父级与全局投影的删除、重命名、定义变更同样传播。
4. 更新全局 registry、总 index 和总术语视图。每个生成文件写临时文件后替换；写入前核对上次读取的摘要，若其他会话已改动则重新合并。跨多个文件的操作记录待同步清单，全部校验后清除；下次 lint 继续修复中断，不能宣称多文件替换天然是事务。

## 分类

默认可配置阈值：单份术语文档超过 **200 条**或 **40 KiB**；单份 index 超过 **100 个链接条目**或 **24 KiB**。这是本技能工程默认值，不是引用作者的规定。局部父级也可应用同样规则。

超限后按稳定的领域分类写 `glossary/<领域>.md`、`indexes/<领域>.md`；仍超限按项目或子领域再分层。根 GLOSSARY/index 保留分类链接、范围摘要、数量与同名异义导航。所有条目都在分类文件中，根路由加分类文件合起来才是“总表”。读取时先路由，再按需打开，不一次加载全部。

迁移保留概念 ID，原有锚点位置留重定向链接，修复登记的入站引用，核对迁移前后概念 ID 集合相等、无重复遗漏。变少后不自动合并，以免链接来回变化。

## 删除

目录消失先标 missing，执行 ftag 定位；查询无结果不等于删除。用户确认删除，或有明确删除操作证据，才标 deleted：移除父级和全局活动索引项；移除仅此项目拥有的活动术语投影；还有活跃权威来源的共享概念继续保留。登记表保留 tombstone（ID、原路径、日期、依据），历史日志可引用 tombstone。引用被删来源的现存页面标为失效或用其他证据修订，不擦除历史掩盖缺口。
